1. 수정 전 구조
홈: 소개 → 대표 용어가 있는 통신 지도 → 접힌 8개 영역 → 웹 접속 7단계. 용어는 설명 창으로 연결.
상세 공통: 제목·목차 → 용어 바로가기 → 동일 용어의 펼침 카드 → 접힌 역할 설명 → 사용 예시 → 접힌 시각화·비교·관련 영역·암기 → 이전·다음.
용어 카드: 별칭·계층·설명·예시·풀명칭·교정 이유·원문·공식 출처·관련 개념.

2. 페이지별 내용

html/structure.html — 통신 구조
역할: 계층 이름을 외웠는데 같은 데이터가 어디서 어떻게 처리되는지 연결되지 않는 문제를 해결합니다. OSI와 TCP/IP는 같은 통신을 서로 다른 역할 구분으로 설명합니다.
사용 예시: 브라우저에서 HTTP/1.1 웹 페이지를 요청할 때
흐름: 응용 데이터 만들기 → 전송과 주소 정보 붙이기 → 링크로 보내고 다시 해석하기

용어: OSI 7계층, 응용 계층, 인터넷 계층, 전송 계층, TCP/IP 4계층, PDU, 캡슐화, 표현 계층
비교: OSI와 TCP/IP는 이어 붙이는 단계가 아닙니다
시각화: 캡슐화·역캡슐화 따라가기
수정: 위 사용 흐름을 최상단에 배치하고 중복 용어 목록을 단일 펼침 목록으로 통합. 비교·원문·계층 해설은 필요할 때 확인.

html/lan.html — 물리 연결·LAN
역할: 케이블로 연결했다고 모든 장치가 같은 방식으로 통신하는 것은 아닙니다. 신호 전달, MAC 기반 전달, VLAN의 범위를 구분해 가까운 장치 사이의 연결을 이해합니다.
사용 예시: 사무실 PC가 프린터로 보내는 통신
흐름: 물리 연결 확인 → 링크 주소 확인 → 프레임 전달 → 다른 VLAN이면 라우팅

html/address-routing.html — 주소·경로

3. 제외 기준
제외: 영문 장식 문구, 중복 조작 안내, 없어진 점선 범례, 원본 개수·집계 제외 등 제작·데이터 관리 설명, 삭제한 검색·문제 기능의 잔여 주석.
유지: 원본 83개와 보충 7개, 계층 분류·캐시·주소·NAT 조건, 원문 교정 이유와 근거, OSI와 학습 순서의 차이.
서버·운영체제·가상화는 기존 학습 자료이므로 유지. 공식 시험 범위를 새로 확인하지 않았으며 범위 밖이라고 단정하여 삭제하지 않음.
원본/보충 표시는 설명 창과 펼친 카드에 유지. 운영 절차는 README에 기록.

4. 가독성 분석 → 수정
용어 이름이 두 번 반복 → 바로가기 목록 제거, 단일 펼침 목록과 기존 term-index 앵커 유지.
용어 나열 뒤에 사용 예시 → 사용 흐름을 먼저 배치.
작은 글씨와 보조 정보의 경쟁 → 본문 16px, 주요 링크와 조작 14px, 보조 배지는 접힌 카드에서 생략.
긴 예시의 세로 나열 → PC 2열 순서 카드, 모바일 1열.
단계 목록의 클릭 가능 여부가 모호 → 네이티브 버튼으로 직접 단계 이동.
접힌 절 제목의 접근성 연결이 끊김 → summary에 제목 ID 부여.

5. 수정 후 구조
홈: 간단한 소개 → 통신 지도·용어 → 선택적 영역 탐색 → 직접 선택 가능한 웹 접속 단계.
상세: 제목·목차 → 사용 흐름·연결 용어 → 단일 용어 목록 → 추가 설명 → 이전·다음.
설명 창: 영역·원본 구분 → 설명 → 실제 예시 → 관련 개념 → 세부 설명.

6. 작업 범위
원본 TXT와 data.js 변경 없음. 검색·문제·오답 기능 재추가 없음.
요청된 본 TXT 파일만 신규 생성. 커밋·푸시·공개 배포 실행 없음.
검증은 이번 화면 변경과 상호작용으로 한정.
